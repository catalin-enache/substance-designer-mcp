# ROADMAP.md: what's still to do

The road map for perfecting this MCP. When an item is done, check it (`[x]` in the Done column)
and document the result as AGENTS.md describes; checked items can be deleted later (git history keeps
the record). Effort is a rough guess: S = under an hour, M = a few hours, L = a day or more.

Numbers are stable IDs (other docs cite them); within a section, the order of the rows is the
priority. Items should come from real use (item 31) more than from reviewing the project itself.

**Fewer tools.** The server went from 43 tools to 35 by turning the single-edit tools into `apply_edits`
ops (fewer choices make the right one easier to pick, and the tool list costs every session tokens).
A new capability is first a parameter or an op of an existing tool; a new tool when it doesn't fit, such as a
workflow of its own (item 33), rather than complicating an existing tool with completely different logic. The items
below are written that way.

## Ideas, not yet decided

Add ideas here before they are prioritised into a table above.

- **The function-graph table on bool and string parameters:** GUIDE.md's table is measured on float4 and enum parameters and `$` ones; nothing says these differ, and nothing has measured them.
- **A `duplicate` op:** the API has no call for it, so it means copying a node's values, `$` inheritance and function graphs by hand. The other MCP's `duplicate_node` copies none of them and refuses library nodes. Only if real use (item 31) keeps needing it.
- **Deleting a graph:** no tool does it. `SDResource.delete()` is in the API (read from Designer 16's file, not run). Destructive, so it would want the same care as item 15, and it may belong with it.
- **Starter node chains for materials:** the other MCP's 79 recipes build whole materials in one call. Only their wiring was checked ("0 port failures, 0 crashes"), not how they look, and they say they come from one professional's 512-node graph, so write our own rather than copying them, and only if item 31 shows agents keep rebuilding the same chains. Designer's own `materials/pbr/...` are already a starting point.
- **Wrong value types in a script:** the other MCP reports that `SDValueInt2` on a float parameter and `SDValueFloat` on an enum silently crash Designer 15. The `set` op converts by the parameter's type, so this reaches only a user's own code. Unmeasured on 16; if measured, only in a Designer the self-test started, since it may crash.
